# swe-env-64k-30045 — Qwen3-235B-A22B-Thinking on SWE-bench Verified

This directory packages the artifacts of a 20-step RL bring-up run on
Qwen3-235B-A22B-Thinking-2507 against a 10-instance SWE-bench Verified
slice, using the `examples/qwen3-235b_fullasync_swe-env/` agentic-coding
stack with `add_slime_metrics` wired in for per-tool / per-sandbox /
per-SWE-bench-outcome / policy-staleness telemetry.

## Run config

- **Slurm job:** 30045 (CANCELLED after step 20, elapsed ~3h35m)
- **Cluster:** 12 H200 nodes — 4 actor (Megatron BF16 weights, FP32 master,
  TP=4 PP=2 CP=4 EP=8 ETP=1, CPU optimizer offload) + 8 rollout (8 SGLang
  FP8 engines × TP=8, DP-attention dp_size=8, ep_size=4)
- **Effective context cap:** CP × max_tokens_per_gpu = 4 × 16,384 = **65,536** (64K)
- **Update-weights interval:** 1 (push after every gradient step) — fully-async
  pipeline, max policy staleness per sample = 1 trainer step
- **Reward:** custom `generate_with_codingagent.reward_func`, surface via
  `add_slime_metrics.reward_func`. Score = 1.0 if `/eval.sh` passes,
  0.05 partial-credit if `submit` was called but tests didn't pass, 0 otherwise
- **Algorithm:** GSPO, `--eps-clip 4e-4`, `--kl-loss-coef 0.00`, `--entropy-coef 0`
- **Sandbox:** Modal sandboxes from `ghcr.io/epoch-research/swe-bench.eval.x86_64.*`
  (Epoch AI's per-instance images), one sandbox per agent rollout, six tools
  exposed: `run_command`, `read_file`, `write_file`, `apply_patch`, `run_tests`, `submit`

## Files

| File | What it is |
|---|---|
| `metrics.json` | Per-step + per-rollout structured metrics (no aggregation). 79 KB. |
| `metrics_report.txt` | Human-readable tables (trainer config, generator config, trainer per-step, generator per-rollout, per-tool aggregates, steady-state means). Generated by `render_metrics_report.py`. |
| `RESULTS.md` | Hand-written per-run analysis with the headline numbers. |
| `compile_metrics_json.py` | Parses a slime SWE-env stdout log → `metrics.json`. Runs offline (`./compile_metrics_json.py --job 30045`). |
| `render_metrics_report.py` | Renders `metrics.json` → `metrics_report.txt` (rich tables). |

(`slurm_stdout.log` and `slurm_stderr.log` from the run live at
`/home/sa-shared/kimbo/slime/mnt/logs/infx-swe-64k-30045.{out,err}`;
not copied here due to the stdout being 6.1 MB.)

## Source-of-truth log line patterns

The compiler script regex-parses these patterns from `slurm_stdout.log`:

| Pattern | Producer |
|---|---|
| `[YYYY-MM-DD HH:MM:SS] model.py:NNN - step N: {...}` | `slime/backends/megatron_utils/model.py` |
| `[YYYY-MM-DD HH:MM:SS] train_metric_utils.py:NN - perf N: {...}` | `slime/utils/train_metric_utils.py` |
| `[YYYY-MM-DD HH:MM:SS] data.py:NNN - rollout N: {...}` | `slime/utils/data.py` (per-batch trainer-side digest) |
| `[add_slime_metrics] rollout N: {...}` | `examples/qwen3-235b_fullasync_swe-env/add_slime_metrics.py:custom_rollout_log_function` |
| `[YYYY-MM-DD HH:MM:SS] timer.py:NN - Timer update_weights end (elapsed: Ns)` | slime's `timer.py` |
| `Running entrypoint for job ...: python3 train_async.py --flag VAL ...` | ray-job submit echo |

## How to regenerate

```bash
# 1. Parse the slurm stdout into structured JSON
./compile_metrics_json.py --job 30045 --out metrics.json

# 2. Render the human-readable tables
./render_metrics_report.py --in metrics.json --out metrics_report.txt
```

Both scripts are uv PEP-723 standalone — no pip install needed.
